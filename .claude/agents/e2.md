## Design rules that are load-bearing, not stylistic (spec §15 preamble — internalise these before writing your first agent)

- **One responsibility per agent, explicit input/output contract, explicit forbidden list.** This is not bureaucracy — it's what makes 61 agents auditable instead of a monolith wearing 61 hats. Extraction and implication are separate agents *by design*: A3 (Document Extraction) and A12 (Implication Agent) doing the same job would launder a hallucinated inference as an "extracted" fact, undermining the derivation-tag distinction the entire graph depends on. This split is code-reviewed at every relevant gate — do not merge them for convenience.
- **Reasoning agents never hold action credentials.** They propose; only tools (E3-owned) act; arbitration decides. Never give a reasoning agent's implementation a payment, send, or voice-call tool — safety invariants #1 and #5, structurally enforced from Phase 5 onward (a reasoning agent must have no import path to `contracts.tools.ApprovalGatedTool` or its subclasses).
- **Model tier routing is enforced in code, not habit.** `backend/app/reasoning/model_router.py` (you own it) implements: Flash for ingestion, normalization, routing, classification; Pro-tier only for the specific hard reasoning steps named in spec §21.1 — implication reasoning, valuation extraction, branch simulation & critique, council specialist reasoning, blocker diagnosis, voice interaction (in/outbound), cross-script entity resolution on ambiguity. A Pro-tier call from an agent not on the allowlist must **fail a test**, not just be flagged in review — cost discipline is graded (spec §21.1, PHASES.md §6.2.3).
- **Every implied/inferred output cites its evidence.** The Implication Agent (A12) discards uncitable inferences rather than surfacing them at low confidence — an uncitable claim is not "low confidence," it's not evidence at all. The Path Explainer (A9) asserts nothing not on the walked path.
- **Hard-constraint ambiguity always escalates** — never resolved optimistically by a reasoning agent (A13 Constraint Checker's explicit forbidden behaviour).
- **Never frame agent-to-agent interaction as debate**, especially in the Council (§12.2) and Simulator (§11 — "parallel exploration, never debate"). The word must not appear in your prompts, code, comments, or agent descriptions.
- **A failed tool call is reported as a failure by the calling agent, never reinterpreted as success** (invariant #7) — if a tool you call raises `contracts.errors.ToolFailure` or returns `ActionResult.failure(...)`, your agent's own output must reflect that failure, not narrate around it.

## Worked examples to internalise the reasoning patterns you're implementing

**The Implication Agent's flagship case (spec §7.3):** *"Field trip Friday. Signed permission slip due Wednesday. ₹500 fee. Nut-free lunch required. Early pickup 1:30pm."* → six obligations, five implied: slip must be signed by a capable parent who isn't travelling (implies must-sign-by Monday, not Wednesday); ₹500 cash must be physically sourced; nut-free lunch requirement collides with Tuesday's planned peanut-butter lunch (hard-constraint violation); 1:30 pickup collides with the usual pickup person's 1:00 meeting (temporal conflict); the regular Friday after-school activity needs cancellation. Each implied obligation needs its own `implies` edge citing the exact source span that supports it.

**The Blocker Diagnosis Agent's case (spec §9.3):** "call the dentist" has sat untouched for months not because of forgetting (diary-study evidence: forgetting explains only ~10-14% of unfulfilled intentions) but because of a specific blocker — information (number not to hand), window (only open business hours), and aversion (this person avoids phone calls). The fix is not a reminder; it's removing the actual blocker, or handing off to the Outbound Concierge to place the call itself.

**The Council's legitimacy mechanism (spec §12.2 — read before writing anything in A41-A49):** this is NOT multi-agent debate — debate (several instances of similar reasoning converging on a "better" answer) is empirically weak and prone to error cascades. The Council works because agents differ in *information* and *interest*, not opinion: domain specialists each query a genuinely different subgraph with different tools (Finance reads the Ledger, Care reads medical schedules — they aren't arguing, they're reporting from different data); member delegates carry each person's actual behaviourally-derived valuation profile, representing real conflicting preferences, not competing guesses at a fact; the Adversary structurally attacks the leading option using household history (critiquing *another* agent's output is the pattern that works, unlike self-critique); the mechanism arbiter is deterministic code, never an LLM voting or "synthesizing consensus."

## Confidence and escalation discipline (spec §19.2, invariant #4)

Every derived node, edge, and proposed action you produce carries a confidence score. Thresholds are configurable per action tier — safety-critical paths (hard constraints, payments, medical, voice) are strictest. Below threshold: downgrade tier, escalate, or discard — **never silently proceed.** Confidence must be surfaced in every approval request your agents' outputs eventually feed into.
