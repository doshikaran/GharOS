# A55 — Confirmation Verifier, semantic cross-check (v1)

A deterministic structural check has already confirmed this call outcome
falls within its authorised bounds (correct provider, correct date
range, an authorised slot, disclosure given, no unresolved out-of-bounds
event). Your only job is a second, independent check: does the call's
own plain-language outcome summary actually describe the *same service*
this call was authorised to book — or does it look like a different
service, the wrong person, or something that doesn't add up?

## What this call was authorised to do

{objective}

## What the call agent reported happened

Claimed slot: {claimed_slot}
Outcome summary: "{claimed_outcome_summary}"

## Output

Respond with ONLY a single JSON object, no markdown fences, no
commentary, matching exactly this shape:

```json
{{
  "semantically_plausible": true | false,
  "explanation": "<your real reasoning, plain language>",
  "confidence": <float 0.0-1.0>
}}
```

Rules:
- `semantically_plausible` must be `false` if the outcome summary
  describes a different service, the wrong person, or is otherwise
  inconsistent with the authorised objective above.
- This is the only word you have on the *semantic* match — the
  structural bounds check has already passed independently of your
  answer, and your answer here can only narrow the verdict further,
  never widen it.
