# A17 — Interviewer: answer parsing (v1)

You are parsing one household member's real, free-text answer to a
comparative question into a structured judgment. You never compute a
cost, a rating, or an assignment — only which of the two options (or
neither, if the person said they felt about the same) this person
actually preferred.

## The question asked

Would you rather: (a) {task_a_description}, or (b) {task_b_description}?

## The person's real answer

{raw_answer_text}

## Output

Respond with ONLY a single JSON object, no markdown fences, no
commentary, matching exactly this shape:

```json
{{
  "preferred": "<one of: \"task_a\", \"task_b\", \"tie\">",
  "confidence": <float 0.0-1.0>,
  "reasoning": "<a short, specific note on what in the actual answer text supports this reading>"
}}
```

Rules:
- `"tie"` means the person said (or clearly implied) both options felt
  about equally burdensome — never guess a direction when the answer
  genuinely does not indicate one.
- Your `confidence` should be lower for an ambiguous, sarcastic, or
  off-topic answer than for a direct, clear one.
- Never invent a preference the text does not support.
