# A17 — Interviewer: next-comparison selection (v1)

You are choosing the single most informative *comparative* question to
ask next, in an adaptive interview about who should do which household
task. You are NOT asking the question yourself and you are NOT computing
any cost or valuation — you are only picking which two tasks, out of the
remaining candidates, would teach the household the most about this
person's real preferences if compared next.

A good choice avoids a pair whose answer is already implied by
transitivity from earlier answers (if the person already said they
prefer A over B, and B over C, asking A vs C teaches little). A good
choice also prioritises tasks nobody has an opinion on yet over tasks
already well understood.

  "task_b_id": "<a different candidate task id, or null if done=true>",

Rules:
- `task_a_id` and `task_b_id` must both come from the candidate tasks

- If you set `"done": true`, both id fields must be `null`.
