# ADR-017: Household Simulator — zero new node/edge types; real Search-grounded external citations; backward mode as a second entry point on the same six agents

**Status:** accepted
**Phase:** 11
**Date:** 2026-08-28

## Context

Spec §15.8 names six agents (A35-A40). Checked directly before writing anything, per this project's own "reuse before invent" discipline (ADR-014, ADR-015, ADR-016): `contracts/graph_types.py` already carries `Decision` (`question`, `trigger`, `status`, `resolution_summary`, `rationale`), `Branch` (`decision_id`, `label`, `projected_impacts: dict[str, str]`, `grounding_refs: tuple[str, ...]`, `critiques: tuple[str, ...]`), and `CouncilPosition` — all frozen since an early phase, all previously unused except incidentally (`app.agents.fair_allocator.renegotiation_trigger_agent` already writes a `Decision`; `backend/seeds/demo_household.py` already seeds one `Decision` + two `Branch`es as illustrative fixture data). `backend/app/graph/decision_repository.py` (`FirestoreDecisionRepository`) already exists, read-only by design ("permanent — never pruned"); `FirestoreGraphWriter.write_node` is generic and already covers writing these types without new repository code. `GraphReader.blast_radius(node, depth)` and `GraphReader.history(entity)` already exist (Phase 1). `Outcome` already carries `variance: float | None` and `attribution_tags: tuple[str, ...]` (the latter a formalized convention since ADR-016).

This means **Phase 11 needs zero new node types and zero new edge types** — the first phase since Phase 6 where that is true of the *entire* phase, not just part of it.

Two genuine gaps remain, both capability gaps (new read logic / new tool surface), not contract gaps:

1. **Cross-entity OUTCOME variance.** `history(entity)` returns outcomes for *one* entity via `completes_into`. A39 Calibration needs "this household's own variance" for a *category* of past decision (e.g. every past relocation, not one specific obligation) — no existing query aggregates across entities by category.
2. **A36's "external data with citations, timestamps, freshness policy."** No existing tool in this codebase does genuine external retrieval for open-ended research (as opposed to `app.tools.provider_search_tool.ProviderSearchTool`, which is an honestly-labeled *synthetic* directory generator — the right call there per its own docstring, because no real Places API is integrated anywhere in this codebase, but the wrong pattern to copy here: Gate 11's own CTO review is "pick any number in the brief and demand its source — if it cannot be produced instantly, the phase fails." A synthetic citation is not a source; it is a citation-shaped fabrication, and would fail that review by design, not by accident).

## Decision — 1: reuse `Outcome.attribution_tags` as the variance category key; one new `GraphReader` op

`GraphReader.outcome_variance(tag: str) -> tuple[Outcome, ...]` — a new method, same status as Phase 4's `dependency_chain` (a justified addition beyond spec §5.7's original 14 enumerated operations, documented as such in its own docstring, not smuggled in as if it always existed). It scans for `Outcome` nodes whose `attribution_tags` contains `tag`, independent of which entity `completes_into` them. No new field on `Outcome` — the tag vocabulary this phase adds (`"relocation"`, `"school_transition"`, `"staff_transition"`, `"major_purchase"`) extends the same convention ADR-016 established for provider-reliability tags, documented in `gharos-graph-model`.

`GraphReader.blast_radius_multi(node_ids: tuple[NodeId, ...], depth: int) -> tuple[object, ...]` — a thin multi-seed convenience wrapper (single traversal pass, correctness-equivalent to calling `blast_radius` once per seed and unioning — a node is included iff its distance from *any* seed is within `depth`). A37 Path Simulator seeds this from every anchor entity the framing step identifies as touching the decision (home, school, staff `Person` nodes, recurring `Obligation`s) rather than one node — "blast radius at decision scale" (E1's own phase work item, PHASES.md Phase 11) means exactly this: one traversal over several real anchors, not a new traversal semantics.

`backend/app/solvers/calibration_stats.py` (E1) — deterministic mean/variance/confidence-band computation over a tuple of `Outcome.variance` floats, mirroring `salary_calculator.py` (Phase 7) and `fair_allocation.py` (Phase 8)'s pattern: an agent never computes statistics itself. A **documented, explicit thin-history threshold, `MIN_SAMPLE_SIZE_FOR_CALIBRATION = 3`** (same threshold precedent as Phase 9's Slippage Analyst N=3, not a new arbitrary number) — below it, `CalibrationEstimate.is_thin_history` is `True` and no numeric confidence figure is produced, only the honest count and a plain statement, per spec §11.5's named failure mode ("Cold start... be honest").

## Decision — 2: A36 uses Gemini's real Vertex AI Google Search grounding tool — genuinely real citations, not synthetic ones

`GeminiClient` (E2, `backend/app/reasoning/gemini_client.py`) gains one new method, `generate_grounded_text(*, agent_id, tier, prompt) -> GroundedGeminiCallResult`, parallel in shape to the three existing `generate_*` methods, going through the same `ModelRouter`/allowlist/failure-handling path. It attaches `types.Tool(google_search=types.GoogleSearch())` to the call's `GenerateContentConfig` and parses the SDK's real `response.candidates[0].grounding_metadata` into a new frozen `GroundedCitation(title: str, uri: str, retrieved_at: datetime)` tuple — `retrieved_at` is `datetime.now(UTC)` at call time, genuinely real regardless of how old the underlying indexed page is (freshness of the *lookup*, not a claim about the *content*'s age — A36 states both honestly, never conflating them).

This is a real Vertex AI capability (Google Search grounding), not a new external integration this codebase has to build or fake — it deepens mandatory requirement #1 ("Gemini 3.5+ via Vertex AI") rather than diluting it. **`response_mime_type` is never set on a grounded call** — tool-use and strict JSON-mode responses are mutually exclusive on the Gemini API's own `GenerateContentConfig`; E2 confirms this against a real live call (not assumed from memory) before writing the parsing path, mirroring this project's own precedent (Phase 2's live stack proof, ADR-010's live Pro-tier call) of never trusting an SDK behaviour claim that hasn't been exercised for real. A new `live_gcp`-marked test (`test_gemini_client.py`'s existing convention, `GHAROS_RUN_LIVE_GCP_TESTS=1`) proves one real grounded call returns at least one real citation with a real, resolvable URI — the CTO runs this personally as part of Gate 11 verification, same as ADR-010's live call.

**Honest fallback, never fabricated:** when Google Search grounding returns zero chunks for a query (a real, expected outcome — grounding does not trigger for every prompt), `GroundingResult.citations` is empty and A36's summary states plainly that no external source was found, rather than inventing one. This is the same "say so, never fabricate" discipline as A39's thin-history case and every prior phase's calibrated-honesty agents (A16, A26, A29).

## Decision — 3: backward mode is a second entry point on the same six agents, not a seventh agent

Spec §15.8's header is explicit: "Household Simulator (**6**)." Backward mode ("take a committed plan → assume it failed → reason backwards using OUTCOME history → identify the likely failure point → hand mitigations to Intention→Action") is assembled from agents already being built this phase, not a new one: A35 frames the backward question ("assume X failed — why?"), A39 Calibration supplies the OUTCOME-variance evidence for the plan's category (reusing `outcome_variance()` unchanged), and A40 Decision Synthesizer narrates the predicted failure point and mitigations as a `BackwardModeAnalysis` — a variant output shape, same agent, same forbidden list (no verdict, only evidence-linked prediction).

**The Intention→Action handoff is informational, not a new write path.** `BackwardModeAnalysis.suggested_mitigations: tuple[str, ...]` is surfaced to the household in the UI; nothing in this phase automatically creates or mutates a Phase 9 `IntentionTrackable`-family object. Auto-writing across subsystem boundaries is a real coupling decision this phase's own gate does not require and three days from the submission deadline is the wrong time to take on speculatively — revisit only if Phase 12 (Council) or Phase 14 (Consolidation) needs it for real.

## Decision — 4: Pro-tier allowlist

`A37`/`A38` were already present in `PRO_TIER_ALLOWLIST` (added ahead of this phase, evidently during an earlier whole-roster pass). Adding `A35`, `A36`, `A39`, `A40` now, each with a spec-citing comment matching the file's existing convention.

## Alternatives considered

1. **A new `SimulationBrief` or `CitedFact` node type.** Rejected — `Branch.projected_impacts`/`grounding_refs`/`critiques` already hold exactly this shape; a `Decision` with its `Branch`es already *is* the brief, queryable via the existing `decisions_touching`/`branches_for` ops. Adding a parallel type would duplicate, not extend.
2. **A synthetic, honestly-labeled grounding tool**, matching `ProviderSearchTool`'s precedent exactly. Rejected for A36 specifically (unlike provider search) because Gate 11's CTO review explicitly demands an instantly-producible source for any number in the brief — a labeled-synthetic citation still fails that review the moment it is checked, whereas a labeled-synthetic *provider listing* was never subject to a "prove this business exists" review. The precedent's honesty principle (never imply realness that isn't there) argues for using the real Vertex AI capability here, since one exists and is reachable within scope.
3. **A seventh "Backward Mode" agent.** Rejected — contradicts the spec's own explicit "(6)" agent count and the "one engine, two query modes" framing (§11.1); reusing A35/A39/A40 is both truer to the spec and less code.

## Consequences

`contracts/graph_types.py` and `contracts/tools.py` unchanged this phase. `backend/app/graph/reader.py` gains `outcome_variance` and `blast_radius_multi`. `backend/app/solvers/calibration_stats.py` is new (E1). `backend/app/reasoning/gemini_client.py` gains `generate_grounded_text`/`GroundedCitation`/`GroundedGeminiCallResult` (E2). `backend/app/reasoning/model_router.py`'s allowlist gains four entries. A new agent package, `backend/app/agents/simulator/` (A35-A40, E2 lead). `gharos-graph-model` SKILL.md documents the `attribution_tags` decision-category vocabulary and the two new `GraphReader` ops as extensions beyond the original 14, matching `dependency_chain`'s own documented precedent.
